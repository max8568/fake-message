# LINE 對話產生器：實作規格

這份規格整理自 [規劃地圖](map.md) 上所有已關閉的單子。照這份規格就可以開始做，不需要回頭翻單子；想知道某個決定為什麼這樣定，再點進對應的單子。

用詞以 repo 根目錄的 [CONTEXT.md](../../CONTEXT.md) 為準，例如我方、對方、匿名頭像、日期分隔線、截圖日期、合併、單頁截圖、長截圖。

---

## 1. 要做出什麼

一個純前端網站。使用者在電腦版 Chrome 上輸入一段 LINE 風格的對話，網站畫出 iPhone 上 LINE 的聊天畫面，並輸出成 PNG。

- 外觀要做到乍看很像 iPhone 版 LINE，不追求逐像素一致。
- 預設不加浮水印。
- 網站介面和截圖上的文字都只有繁體中文。

## 2. 範圍

**要做**

- 個人對話、群組對話
- 淺色、深色模式（每段對話自己設定）
- 文字訊息，可以打 emoji
- 日期分隔線，依訊息日期自動產生
- 每則訊息的日期、時間、已讀
- 同一個人、同一分鐘內的訊息自動合併
- 整段對話的設定：標題列、手機狀態列、輸入框、12／24 小時制、截圖日期
- 12 個內建匿名頭像
- 瀏覽器裡存多段對話，可以匯出、匯入 JSON
- 兩種輸出：單頁截圖、長截圖
- 授權說明頁

**不做**

- Android 版 LINE 的外觀
- 文字以外的訊息：貼圖、照片、LINE 自家的表情貼、回覆、收回、系統訊息、通話紀錄、語音、網址預覽
- 動畫或影片輸出
- 上傳自己的頭像或圖片
- 繁體中文以外的語言
- LINE 字體大小設定
- 帳號、登入、後端儲存
- 同一段對話同時保留兩種視角（要另一個人的視角，就複製對話再換我方）
- 手機版的編輯介面
- 自訂聊天背景色、背景圖
- 390pt 等其他 iPhone 尺寸

## 4. 資料

### 4.1 一段對話有什麼

| 欄位 | 說明 | 預設值 |
|---|---|---|
| 對話模式 | 個人對話或群組對話 | 新增時選 |
| 參與者 | 見 4.2 | 個人對話：我方加一位對方；群組：我方加兩位對方 |
| 我方 | 參與者中的一位，可以改成另一位 | 第一位參與者 |
| 訊息 | 依序排列，見 4.3 | 空的 |
| 群組名稱 | 只有群組對話有 | 使用者填 |
| 群組人數 | 標題列括號裡的數字。不能比參與者人數少 | 參與者人數 |
| 外觀 | 淺色或深色 | 淺色 |
| 12／24 小時制 | 影響訊息時間和狀態列時間 | 24 小時制 |
| 截圖日期 | 用來判斷「今天」「昨天」 | 最後一則訊息的日期 |
| 狀態列時間 | | 最後一則訊息的時間 |
| 靜音圖示 | 開或關 | 關 |
| 電量 | 0–100 | 100 |
| 訊號 | 0–4 格 | 4 |
| 網路 | Wi-Fi、5G、4G、不顯示 | Wi-Fi |
| 未讀數 | 0–999，0 表示不顯示 | 0 |
| 顯示輸入框 | 只影響單頁截圖 | 顯示 |
| 最後修改時間 | 對話清單排序和顯示用 | 自動 |

**規則**

- 個人對話只能有一位對方。對方有兩位以上時，不能切換成個人對話。
- 群組對話至少要有兩位對方。

### 4.2 參與者

| 欄位 | 說明 |
|---|---|
| 名字 | 使用者填 |
| 頭像 | 12 個內建匿名頭像之一，見第 9 節 |

- 新增參與者時，自動挑一個這段對話裡還沒人用的頭像，之後可以換。
- 12 個都用掉之後允許重複，不擋也不跳警告。

### 4.3 訊息

| 欄位 | 說明 | 新增時的預設值 |
|---|---|---|
| 發話者 | 一位參與者 | 輸入區選的人 |
| 內容 | 文字，可以換行，可以有 emoji | 使用者輸入 |
| 日期 | | 跟上一則相同；第一則是今天 |
| 時間 | 到分鐘 | 跟上一則相同；第一則是現在 |
| 已讀 | 開或關。只有我方的訊息會顯示，但每則訊息都存著這個設定 | 開 |
| 已讀人數 | 只有群組用。0 到「群組人數減 1」 | 群組人數減 1 |

**規則**

- 訊息照清單順序顯示，不依時間重排。時間倒退時不擋，也不跳警告。
- 換我方時，每則訊息的已讀設定不會改。原本我方的已讀只是被藏起來，換回來時又會出現。
- 網站不檢查「後面的訊息已讀、前面的沒讀」這種情況。

### 4.4 儲存

- 每次修改都自動存進瀏覽器，沒有「儲存」按鈕。資料只有文字和頭像編號，一段對話只有幾 KB，用 `localStorage` 就夠了。
- 打開網站時，顯示最後修改的那一段對話。
- 第一次打開網站時，放好兩段範例對話：一段個人對話、一段群組對話，並顯示個人對話那段。範例跟一般對話一樣可以改、可以刪，刪掉後不會再出現。

### 4.5 匯出和匯入

- **匯出這段**：下載目前這段對話的 JSON。
- **匯出全部**：下載所有對話的 JSON，給使用者備份用。瀏覽器清掉網站資料時，對話會全部不見。
- **匯入**：讀取上面兩種 JSON 檔。匯入的對話一律新增成新的對話，不覆蓋任何現有的對話。
- **格式版本號**：匯出的 JSON 最外層要有格式版本號，從 1 開始。網站改版、資料格式變了，就把版本號加 1，並寫好把舊版本轉成新版本的程式，讓舊檔案還能匯入。

## 5. 編輯介面

整個畫面分成三欄。只做電腦版，不做手機版的版面。參考試做檔 [prototype/editor-prototype.html](prototype/editor-prototype.html) 的 `?variant=D`。

| 位置 | 內容 |
|---|---|
| 左欄上半 | 對話清單 |
| 左欄下半 | 輸入訊息區 |
| 中間 | 只放手機預覽，不放任何按鈕 |
| 右欄 | 輸出（「單頁截圖」「長截圖」「下載 PNG」）、參與者、對話設定 |

### 5.1 對話清單

- 每段對話顯示三樣資訊：
  - 標題列上的名字：個人對話顯示對方的名字，群組顯示「群組名稱 (人數)」
  - 我方是誰
  - 最後修改時間
- 清單上不另外取名字。
- 按鈕：
  - 新增個人對話
  - 新增群組
  - 複製
  - 刪除：刪除前跳一次確認，刪了不能復原
  - 匯出這段
  - 匯出全部
  - 匯入

### 5.2 輸入訊息區

- 上方是參與者的頭像標籤，點一下選這則訊息是誰說的。我方的標籤要標「我方」。
- 下方是文字框：
  - Enter 送出，Shift+Enter 換行。
  - Tab 換下一位發話者。
  - 用注音輸入法選字時按的 Enter 不能送出，要檢查 `isComposing`。

### 5.3 修改訊息

- 點預覽裡的訊息，會跳出一個小視窗。小視窗固定在手機預覽的左側，底部跟手機預覽底部對齊，不蓋到聊天畫面，也不跟著被點的訊息上下移動。小視窗裡可以：
  - 改發話者
  - 改內容
  - 改日期、時間
  - 改已讀：只有我方的訊息有這個選項；群組多一個已讀人數
  - 上移、下移
  - 刪除
- 在小視窗裡改的東西，要即時反映在預覽上。
- 被點選的訊息在預覽裡要有外框標示。
- 在預覽裡直接拖拉訊息，可以排序。

### 5.4 參與者

- 每位參與者可以改名字、換頭像、設為我方、移除。至少要保留個人對話或群組對話需要的人數。
- 移除參與者時，這個人發的訊息一起刪除。
- 群組對話才有「新增參與者」。

### 5.5 對話設定

右欄放 4.1 表格裡所有可以改的設定。只影響單頁截圖的設定，要放在同一區，並標明「單頁截圖才有」：狀態列時間、靜音、電量、訊號、網路、未讀數、輸入框。

### 5.6 手機預覽

- 中間的預覽依視窗高度自動縮放，整支手機一次看得完，不用捲動。
- 長截圖模式下，預覽可以上下捲動。

## 6. LINE 畫面的繪製規則

### 6.1 兩種輸出

| | 單頁截圖 | 長截圖 |
|---|---|---|
| 模仿什麼 | iPhone 整個螢幕的原始截圖 | LINE 內建「截圖」功能的輸出 |
| 畫面寬度 | 440pt（iPhone 17 Pro Max） | 440pt |
| 狀態列、標題列 | 有 | 沒有 |
| 輸入框 | 有，可以關掉 | 沒有 |
| 高度 | 固定 956pt | 依內容 |
| 訊息太多時 | 只顯示最後一個螢幕的內容，上面的被切掉 | 整段對話都放進去 |
| 輸出 PNG | 1320×2868px（3 倍） | 880px 寬（2 倍），高度依內容 |
| 高度上限 | 沒有 | 16,384px，見 6.8 |

不提供其他組合，例如有狀態列但長度不限的截圖。真的 iPhone 和 LINE 都做不出這種圖。

### 6.2 日期分隔線

- 第一則訊息前面一定有一條日期分隔線。
- 之後，前後兩則訊息日期不同時，中間自動插一條。日期往回跳也照插。
- 日期分隔線不是對話裡的項目，不能手動新增或刪除。
- 寫法：

| 情況 | 寫法 |
|---|---|
| 截圖日期當天 | 今天 |
| 截圖日期前一天 | 昨天 |
| 跟截圖日期同一年的其他日子，包含比截圖日期晚的日子 | 8/31 (週一) |
| 跟截圖日期不同年 | 2025/8/31 (週日) |

日期寫法要注意：
- 月、日不補零。
- 日期和括號之間有一個半形空格。
- 括號是半形。

### 6.3 時間

- **24 小時制**：寫成 `10:01`，小時補零。
- **12 小時制**：寫成 `上午 10:01`、`下午 3:45`。小時不補零，中午 12 點是 `下午 12:00`，午夜 12 點是 `上午 12:00`。
- 狀態列的時間也照這個設定，但狀態列不寫「上午」「下午」，只寫數字。

### 6.4 連續訊息的合併

- 三個條件都成立時，前後兩則訊息合併：
  - 同一位參與者發的
  - 日期和時間（到分鐘）都相同
  - 中間沒有日期分隔線
- 合併後：
  - 只有第一則顯示頭像、名字和尾巴
  - 只有最後一則顯示時間和已讀
- 不能手動指定要不要合併。
- 合併後的訊息，彼此的上下間隔比一般訊息小，見數值表。

### 6.5 我方和對方的訊息

**我方**
- 氣泡靠右。
- 已讀和時間在氣泡左邊，靠氣泡底部對齊，分兩行，文字靠右對齊：
  - 第一行：個人對話寫「已讀」；群組寫「已讀 N」，N 是已讀人數。N 是 0 時，這一行不顯示。
  - 第二行：時間。
- 已讀關掉時，只顯示時間。
- 不顯示頭像和名字。

**對方**
- 頭像在最左邊，跟氣泡頂端對齊。
- 群組對話：名字在氣泡上方，左邊跟氣泡對齊。
- 個人對話：有頭像，沒有名字。
- 時間在氣泡右邊，靠氣泡底部對齊，只有一行。
- 不顯示已讀。

**氣泡的尾巴**
- 是一個小勾，往外凸約 4–5pt。
- 我方的在氣泡右上角，對方的在左上角。
- 只有合併後的第一則有尾巴。

**換行**
- 內容裡的換行要照樣顯示。
- 太長的一行在氣泡最大寬度處自動換行。很長的網址或英文單字，也要能在中間斷行。

### 6.6 狀態列（只有單頁截圖有）

- **左邊**：時間，粗體。靜音打開時，時間右邊多一個靜音鈴鐺。
- **右邊**依序是：
  - 訊號：4 格由矮到高，沒訊號的格子顏色變淡
  - 網路：Wi-Fi 圖示，或「5G」「4G」字樣；選「不顯示」就什麼都不畫
  - 電池：圖示裡直接寫電量數字。電量低於 20 時，電池變紅色 #FF3B30
- iPhone 截圖本來就不會拍到動態島，所以不用畫。

### 6.7 標題列和輸入框（只有單頁截圖有）

**標題列**
- 左邊依序是：返回箭頭、未讀數（0 就不顯示）、標題。
- 標題：
  - 個人對話：對方的名字，不能另外改。
  - 群組：「群組名稱 (群組人數)」，人數前面有一個半形空格。
- 右邊四個圖示，個人對話和群組都一樣：搜尋、通話、記事本、選單。
- 標題列下緣有 1pt 分隔線。

**輸入框**
- 左邊三個圖示：＋、相機、相片。
- 中間是膠囊形的輸入欄，裡面左邊是「Aa」，右邊是笑臉圖示。
- 右邊是麥克風。
- 下面留白到螢幕底部，是 iPhone 底部指示條的位置，但不畫指示條。

### 6.8 長截圖的高度上限

- 輸出的 PNG 最高 16,384px，等於畫面上的 8,192pt。以單行訊息估算，大約可以放 186 則。
- 用畫出來的實際高度判斷，不是用訊息則數判斷。
- 超過上限時：
  - 「下載 PNG」按鈕不能按
  - 顯示「對話太長，請複製成兩段」
- 不使用 snapdom 的分段接圖功能。

## 8. 字型和 emoji

- 中文用 Noto Sans TC，英文和數字用 Inter，emoji 用 Noto Color Emoji。三套都從 Google Fonts 載入，都是 OFL 授權。
- CSS 的字型順序：`"Inter", "Noto Sans TC", "Noto Color Emoji", sans-serif`。
- 頁面要標 `lang="zh-Hant-TW"`。沒標的話，英文版 Windows 會把頁面當成簡體中文。
- 輸出 PNG 前，要等對話裡用到的字都載入完成（例如等 `document.fonts.ready`，再對對話裡的文字做 `document.fonts.load`），再交給 snapdom。
- 少見字不另外補。Google Fonts 版的 Noto Sans TC 沒有的字，會用電腦本身的字型顯示。
- 不能用的字型：蘋方、SF Pro、Apple 的 emoji。授權不允許放在網站上。

## 11. 驗收

- 只在電腦版 Chrome 上測。
- 畫面像不像，由使用者看過覺得像就算通過。不另外做比對頁，也不訂數字門檻。
- 功能要逐項確認：
  - 個人對話、群組對話
  - 淺色、深色模式
  - 12／24 小時制
  - 日期分隔線的四種寫法
  - 連續訊息的合併
  - 已讀的顯示規則
  - 換我方
  - 複製、刪除、匯出、匯入
  - 單頁截圖、長截圖
  - 長截圖超過上限時的提示
- snapdom 升級前，要在 Chrome 上重新測過單頁截圖和長截圖。

## 12. 沒有實際截到、靠推測決定的事

做好之後，如果使用者發現跟真的 LINE 不一樣，從這幾項開始改：

- 12 小時制的時間寫法（「上午 10:01」）
- 「昨天」，以及跨年時的日期寫法
- 我方的訊息合併後，已讀和時間只顯示在最後一則
- 深色模式下標題列的未讀數顏色
- 未讀數超過 999 時的寫法（目前上限就是 999）
- 合併後兩則訊息的上下間隔（4pt）

## 13. 整理規格時補上的細節

下面幾項在討論時沒有問過，是整理規格時補上的，使用者可以推翻。

| 項目 | 規格寫的 | 為什麼這樣補 |
|---|---|---|
| 存在瀏覽器的哪裡 | `localStorage` | 資料只有文字和頭像編號，量很小 |
| 移除參與者時 | 這個人發的訊息一起刪除 | 訊息一定要屬於某一位參與者，留著會找不到發話者。試做版也是這樣做 |
| 個人對話和群組對話互相切換 | 對方有兩位以上時，不能切成個人對話 | `CONTEXT.md` 定義個人對話只有一位對方 |
| 新增群組時的參與者 | 我方加兩位對方 | 群組至少要有兩位對方 |
| 12 小時制時的狀態列 | 只寫數字，不寫「上午」「下午」 | iPhone 狀態列在 12 小時制時本來就不寫上午、下午 |
| 12 小時制的中午和午夜 | 中午 12 點寫「下午 12:00」，午夜 12 點寫「上午 12:00」 | 照 iPhone 一般的寫法推測 |
| 已讀人數是 0 時 | 「已讀」那一行不顯示 | 真的 LINE 沒有人讀時不會寫「已讀 0」 |
| 輸出前等字型 | 等 `document.fonts.ready`，再載入對話裡用到的字 | 字型還沒載入就轉圖，會變成預設字型 |
