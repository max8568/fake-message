# 時間和已讀的規則

Map: [LINE 對話產生器](../map.md)
Type: grilling (HITL)
Status: resolved
Blocked by: 01

## Question

依照參考截圖上 LINE 實際的寫法，決定：

- 訊息時間的格式（「上午 10:23」或「10:23」，要不要能切換 12／24 小時制）
- 日期分隔線的寫法（「今天」「昨天」「10/5（日）」「2025/10/5（日）」各在什麼時候出現）
- 新增訊息時時間怎麼自動往後加，跨過午夜時要不要自動插入日期分隔線
- 群組已讀人數的預設值和上限，個人對話已讀的開關
- 連續訊息的合併規則：實機截圖顯示，只有同一個人、同一分鐘內的訊息會合併，合併後只有第一則顯示頭像、名字和尾巴，只有最後一則顯示時間。要照這個規則自動判斷，還是讓使用者自己指定哪幾則要合併
- 實機截圖沒有截到 12 小時制、「昨天」、跨年的日期，這幾種寫法要用推測的方式決定

參考：[research/01-reference-observations.md](../research/01-reference-observations.md)

## Answer

**日期分隔線自動產生，不能手動插**
- 每則訊息都有日期和時間。
- 前後兩則訊息的日期不同時，中間自動插一條日期分隔線。日期往回跳也照插。
- 日期分隔線不是對話裡的一個項目，是從訊息日期算出來的。

**截圖日期**
- 每段對話有一個「截圖日期」，用來判斷哪一天算「今天」「昨天」。
- 預設是最後一則訊息的日期，可以自己改。

**日期分隔線的寫法**（「昨天」和帶年份的寫法沒有在截圖裡看到，是推測的）

| 情況 | 寫法 |
|---|---|
| 截圖日期當天 | 今天 |
| 截圖日期前一天 | 昨天 |
| 跟截圖日期同一年的其他日子，包含比截圖日期晚的日子 | 8/31 (週一) |
| 跟截圖日期不同年 | 2025/8/31 (週日) |

**12／24 小時制**
- 每段對話可以切換，預設是 24 小時制，寫成「10:01」。
- 12 小時制寫成「上午 10:01」「下午 3:45」。這是推測的寫法。
- 手機狀態列的時間也跟著這個切換。

**新增訊息時的預設時間**
- 跟上一則同一天、同一分鐘。同一個人連發的訊息會自動合併，要分開就自己改時間。
- 第一則訊息預設是現在的日期和時間。

**連續訊息自動合併**
- 合併條件：同一個人發的、同一分鐘內、中間沒有日期分隔線。三個條件都成立才合併，不能手動指定。
- 合併後，第一則顯示頭像、名字和尾巴，後面幾則都不顯示。
- 合併後，只有最後一則顯示時間和已讀。我方訊息沒有在截圖裡看到合併的例子，這點是照對方的情況推測的。

**已讀**
- 我方的新訊息預設是已讀。個人對話顯示「已讀」，群組顯示「已讀 N」。
- 群組的 N 預設是「群組人數減 1」，可以改成 0 到「群組人數減 1」之間的任何數字。
- 群組人數就是標題列括號裡的數字，在「整段對話設定的選項」決定。群組人數可以比對話裡的參與者多。
- 真的 LINE 不會出現「後面的訊息已讀、前面的沒讀」，但網站不檢查這種情況。

**訊息的順序**
- 照清單排列的順序顯示，不會依時間自動重排。
- 時間倒退時不阻擋，也不跳警告。
